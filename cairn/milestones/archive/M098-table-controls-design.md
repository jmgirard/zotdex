# M098: Give the table controls one design

**Status:** done (2026-11-05, PR #837 https://github.com/jmgirard/zotero-plugin-index/pull/837)

**Goal:** The home page's search box, filter menus, version buttons, sort menu, count, and pager share one look and one card with the table, with their function unchanged.

**Outcome:** `site/src/pages/index.astro` holds `.table-panel`, which holds `.controls` (search, category, language, version) and `.results` (count, sort), each hidden in the HTML, then `.table-card` and the pager. The script's `closest("[hidden]")` calls unhide the two groups with no script change; `src/site/home-filter.ts` changes only comments. `site/src/layouts/Base.astro` has one rule for the controls' size, edge, and text (2rem, `--faint`, `--radius-m`, `--text-m`), one label rule that matches the table's "Plugin" header, and one hover rule with `background-color`. The pressed version button takes `--hover`, weight 600, and a 2 px inset `--accent` bar, the user's choice over the solid fill. `.controls` steps at 62.5rem (search on its own row), 47.5rem (version buttons on their own row), and 21.25rem (one column), so they follow browser text size. `.table-panel` hides no overflow; `.table-card:has(+ .pager[hidden])` rounds its foot. The dead `.toolbar p` rule that cancelled the count's auto margin is gone. At 1200 px the rows start 133 px below the intro (105 before), and at 375 px 243 px (288 before). The user chose this layout from two mockups on the real page, and the build ran at once after the merge at the user's choice. Tests: markup and edge expectations updated, `--accent` on `--hover` added; no `homeScript` behavior expectation changed.

**Decisions:** none promoted. Milestone-local: side-by-side menus at phone widths, which keep the rows higher than a stack but cut long closed names.

No row graduated or unparked. ROADMAP over its byte budget, so five rows were compressed. Lessons: 13 marked used M098, 1 captured; evicted by rank: 2026-10-27 (M030, used M087).
