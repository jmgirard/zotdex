# M102: Move the site to a jmgirard.com subdomain

**Status:** done (2026-11-05, PR #846 https://github.com/jmgirard/zotero-plugin-index/pull/846)

**Goal:** Serve the site and its data at `https://zotero-plugins.jmgirard.com/` before the index is advertised, with GitHub forwarding the old github.io addresses there (D-068).

**Outcome:** `site/src/base.ts` sets `BASE` to `/` and `ORIGIN` to `https://zotero-plugins.jmgirard.com`, so every site link, canonical link, `og:url`, and `sitemap.xml` entry follows. `site/src/pages/robots.txt.ts` writes a root `robots.txt` that allows every path and names the sitemap. `PREVIOUS_URL` in `src/build/previous.ts`, both `--previous` lines in `build.yml`, and the `$id` of each schema that `writeData` publishes name the new host; `test/schemas.test.ts` checks the written schemas. The link sweep in `test/site.test.ts` refuses a scheme-less value not starting with `/`, starting with `//`, or on the old path. README, DESIGN, CHANGELOG, and the M015 and M035 lessons give the new address and say old addresses forward but a script in another site's page must use the new data URL. After the merge the repo's Pages custom domain was set, the certificate came in about 60 s, HTTPS is enforced, and build run 42145524285 deployed: its `--previous` reads used the new URL (1 record kept earlier facts, 1673 start results carried). The old address answers 301 to the same path and query on the new host, with no Access-Control-Allow-Origin header. The repo homepage names the new address. The user added the Cloudflare CNAME (DNS only) and verified jmgirard.com on the GitHub account.

**Decisions:** D-068 (the move, the forward, and the browser-script cost, accepted). AC4 narrowed to the schemas the build publishes, as `delisted.schema.json` is internal.
